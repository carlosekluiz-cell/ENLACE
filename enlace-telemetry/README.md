# Enlace — telemetry pilot

This folder is the **self-contained Enlace telemetry pilot**: everything needed to
demo the product to a fibre operator (e.g. Community Fibre) and nothing else. The rest
of the parent monorepo is the separate Brazil/ENLACE platform and is unrelated.

**Enlace** is a vendor-agnostic PON/OLT telemetry product. **Pulso Technologies Limited**
(UK-registered) is the company behind it.

```
enlace-telemetry/
├── agent/      Rust telemetry agent — collection, edge fault detection, CSV audit, HTTP audit server
├── site/       enlace.network marketing site (Next.js) — incl. the free /upload CSV audit tool
├── samples/    Reproducible demo data (Adtran SDX 6320 CSV) + generator
├── outputs/    Validation fixtures (UK blind-validation scorecard, incident benchmark) used by the agent test suite
└── docs/       Community Fibre outreach email + one-page explainer
```

> These two trees (`agent/`, `site/`) are copies lifted out of the monorepo
> (`pulso-agent/`, `enlace-site/`). The monorepo originals are untouched. This folder
> can be promoted to its own git repo later (`git init` here).

## The pilot flow

An operator exports an ONT/optical-power report from one OLT as a CSV, uploads it at
`enlace.network/upload` (no install, nothing touches their network), and gets back a full
audit: health score, fibre-cut / power events, ghost connections, at-risk customers,
capacity hot-spots, and prioritised tickets.

Under the hood the site `POST`s the file to the agent's `/audit` endpoint and renders the
JSON it returns.

## Run the demo locally

**1. Build + start the audit server** (the agent). Pick a free port — `8080` may be taken:

```bash
cd agent
cargo build --release
./target/release/pulso-agent --serve-port 8791
#   GET  /health        -> "ok"
#   POST /audit         -> { audit_id, result }   (multipart: file=<csv>, vendor=adtran)
#   GET  /audit/:id     -> { audit_id, result }
```

**2. Start the site, pointed at the agent** (the env var is inlined at build/dev time):

```bash
cd site
npm install
NEXT_PUBLIC_AUDIT_SERVER=http://localhost:8791 npm run dev   # http://localhost:3000
```

Open `/upload`, drop in `samples/community_fibre_adtran_sdx6320.csv`, and it redirects to
`/platform/audit/<id>` with the dashboard (health score, findings sidebar, ONT table).

### One-shot audit (no server, no browser)

```bash
cd agent
./target/release/pulso-agent --audit-csv ../samples/community_fibre_adtran_sdx6320.csv | jq .summary
```

## The sample data

`samples/community_fibre_adtran_sdx6320.csv` is a reproducible 7-day export of ~52 ONTs
across 4 PON ports, generated by `samples/generate_sample.py` (fixed seed). It is seeded
with realistic faults so the audit surfaces real findings:

| Seeded pattern | What the audit reports |
|---|---|
| Fibre cut on a PON branch (LOS) | fibre-cut fault event + offline ONTs |
| Area event (LOS + dying-gasp) | "mixed" fault — power vs fibre, differentiated |
| 2 ONTs drifting −22 → −29 dBm | signal degradation / churn risk |
| 1 flat-Rx always-online ONT | ghost connection (no real traffic) |
| 1 rapidly flapping ONT | flapping / instability |

Current expected result: **health score 52**, 52 ONTs (48 online / 4 offline), 3 fault
events, 1 ghost, 3 churn risks, 2 tickets. Regenerate with:

```bash
cd samples && python3 generate_sample.py > community_fibre_adtran_sdx6320.csv
```
